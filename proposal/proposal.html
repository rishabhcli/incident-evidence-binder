Incident Evidence Binder

UGREEN Hackathon 2026 on AI NAS | Round 1 Proposal | Track: Open Innovation
Entrant: Rishabh Bansal

1. What it does

It builds a time-ordered, hash-checked evidence binder for one incident, such as a water leak, from camera events, photos and documents on the NAS, and later re-checks it.

2. Target user and problem

Homeowners and renters who need proof for an insurance claim, landlord or police report. Their evidence is scattered across camera history, photos and PDFs, and gaps surface only after filing.

3. Solution

The Skill reads the user's own policy or lease to list the proof it requires, matches that list against what the NAS holds, and shows the gaps. After approval it copies chosen files into a new folder with a timeline and a SHA-256 manifest.

4. Main user flow

The user names an incident window and confirms the scope, reviews a timeline, requirement checklist and gap list, then approves items. A hash report follows. Later, "check my evidence binder" reports unchanged, changed, missing and added files.

5. Difference

Photo and document Skills sort by topic. This one centers on a single incident, starts from what the user's own policy demands, merges three sources into one chronology, never touches originals, and shows later whether copies changed. It does not identify people.

6. NAS features used

By SKILL.md build step: 2 user directory lookup; 3 and 7 camera events and evidence; 4 photo search, metadata, vision description, OCR; 5 file search plus document answering, extraction, reconcile; 8 folder creation and copy; 9 SHA-256; 10 knowledge save-text; 12 tags. Footage and documents stay on the NAS.

7. Technical approach

Markdown orchestration. The parent Skill sends delegate commands to the file, security-monitor, photo, document and knowledge experts, passing each real result to the next step. Inputs: incident window, baseline window, cameras, folders, policy file. Reads follow scope confirmation; writes go only into a new folder after plan approval. Models belong to the experts; the Skill calls no outside API.

8. Status

Built: SKILL.md and four reference pages, drafted with an AI agent running Claude models, passing the Starter Kit static checker with zero findings. Not built: nothing has executed. Needs NAS testing: every delegation, snapshot saving, approval prompts, hash comparison, count limits.

9. Validation plan

Test 1: build from synthetic photos, an invented policy and a receipt; check timeline, checklist, copies, matching hashes, untouched originals. Test 2: alter one copy, remove another, add a file; verify mode must report all three and write nothing. Edge case: an empty window must report zero matches, create nothing and substitute no other dates.

10. Limits and dependencies

Never run on a NAS; the catalog marks action stability unknown. Camera evidence may be only a temporary reference, and cameras must be registered. AI descriptions can err, so the user reviews first. The manifest shows copies matched when made, not that originals were genuine; it is not legal advice.
